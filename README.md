# Modus Voice — система обратной связи и предложений сотрудников

Хакатон ГК «Модус Трейд». Сотрудник за минуту сообщает о проблеме или предлагает улучшение, система сама направляет обращение ответственному со сроком ответа, а автор видит решение. Все обращения и решения сохраняются, поэтому руководство видит повторяющиеся проблемы и реально внедрённые улучшения.

**Формат результата:** работающий MVP (ТЗ п. 4.3). Сверка с ТЗ: [docs/TZ_COMPLIANCE.md](docs/TZ_COMPLIANCE.md).

## Быстрый запуск

### Вариант 1. Go + npm (рекомендуется для демо)
Нужны Go 1.26+ и Node.js 22+ (вместе с npm). Установка для Windows:
- Go: https://go.dev/dl/ (установщик `.msi` для Windows)
- Node.js: https://nodejs.org/en/download (установщик `.msi` для Windows)

Проверка: `go version` и `node -v`.

1. Собрать интерфейс (результат попадёт в `backend/internal/webui/dist`, откуда его раздаёт сервер):
```cmd
cd web
npm ci
npm run build
```
2. Запустить сервер с демо-данными на :8080.

PowerShell (Windows):
```powershell
cd backend
$env:DEMO_MODE = "true"
go run ./cmd/server --seed
```
cmd (Windows):
```cmd
cd backend
set DEMO_MODE=true
go run ./cmd/server --seed
```
Откройте http://localhost:8080.

### Вариант 2. Docker (не рекомендуется для демо)
Требует работающий Docker Desktop; первая сборка долгая (скачивание образов и зависимостей), а при сбое движка Docker Desktop сборка может упасть.
```cmd
docker compose up --build
```
Откройте http://localhost:8080. Данные синтетические, загружаются автоматически при первом запуске.

Разработка: сервер из шага 2 в одном терминале, `cd web && npm run dev` в другом (http://localhost:5173, прокси на :8080). Интерфейс без бэкенда: `cd web && npm run dev:mock`. Тот же запуск короче через `make`: `make web-build`, `make backend-demo`.

## Известные ограничения
- Данные синтетические; хранилище SQLite (один узел). Переход на PostgreSQL описан в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Анонимность: скрывается только имя аккаунта. У анонимного обращения нет автора в БД, токен хранится только как SHA-256. Потерянный токен восстановить нельзя. Содержание, вложения и время могут подсказать личность автора.
- Блокировка спама привязана к браузеру (cookie `mv_anon_blocked`): очистка cookie или другой браузер снимают блок. Отметку спама в интерфейсе отменить нельзя.
- Telegram: учётные записи привязываются навсегда (один сотрудник — один чат). Бот работает только при `TELEGRAM_BOT_TOKEN` в `.env` (см. `.env.example`).
- Оргструктура плоская (подразделение → руководитель), без иерархической эскалации.
- Обращение после закрытия не открывается повторно: автор создаёт новое со ссылкой на старое.
- Ограничитель попыток входа считает по адресу соединения; за обратным прокси его нужно настроить отдельно.
- Ручной проход с экранным диктором и измерение контраста всех тем не проводились (см. [docs/QUALITY_SCORECARD.md](docs/QUALITY_SCORECARD.md)).

## Структура проекта
```
backend/            Go: cmd/server, internal/{app,platform,modules,integrations,seed,webui}, migrations
  internal/modules/ identity · org · requests · insights · notifications · telegram (одинаковая структура модуля)
web/                React + TypeScript + Vite: src/{app,shared,features}, e2e
docs/               PRD, ARCHITECTURE, UX_SPECIFICATION, INTEGRATIONS, TZ_COMPLIANCE, api/openapi.yaml
DEMO_SCRIPT.md      сценарий показа, ограничения, ответы на три ключевых вопроса ТЗ
```
Новый модуль = папка в `backend/internal/modules/` + строка в `backend/internal/app/modules.go`; новая фича интерфейса = папка в `web/src/features/` + запись в роутере. Подробности: [backend/README.md](backend/README.md), [web/README.md](web/README.md).
